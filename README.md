## 6. 能否选择退出将个人数据用于模型训练？

**原文标题**: Can I opt out of my input or output data being used for training?

**原文链接**: [https://help.mistral.ai/en/articles/455207-can-i-opt-out-of-my-input-or-output-data-being-used-for-training](https://help.mistral.ai/en/articles/455207-can-i-opt-out-of-my-input-or-output-data-being-used-for-training)

在特定情况下，用户与Mistral的交互数据（对话、文档等）可能被纳入模型训练，但用户拥有完全控制权，可随时退出。退出方式因平台而异：Vibe平台方面，普通用户默认未退出，可在管理面板的"管理→Vibe→隐私"中关闭"允许使用交互数据训练模型"开关；企业版默认已退出，由管理员统一管理。需注意，上传至Vibe的文档同样视为输入数据。移动端（iOS/Android）可在"设置→数据与账户控制"中取消勾选"启用数据共享"。Mistral Studio及API服务的退出则需在管理面板"隐私"菜单下的"匿名改进数据"中关闭对应开关。用户须注意：Vibe与API的退出开关相互独立，关闭一项不代表另一项也已关闭，需分别配置。一旦退出确认，Mistral将不再使用该用户的任何输入或输出数据进行模型训练。

## 10. 嵌入式异步Rust运行时与C语言RTOS的性能对比

**原文标题**: Embedded Rust RTOS vs. C RTOS

**原文链接**: [https://tweedegolf.nl/en/blog/65/async-rust-vs-rtos-showdown/](https://tweedegolf.nl/en/blog/65/async-rust-vs-rtos-showdown/)

摘要：本文在STM32F446ZET6（180MHz）平台上，将Embassy异步Rust与FreeRTOS/C进行正面对比。作者先阐述了两种模型的核心机制：异步Rust基于Future状态机与Waker唤醒机制，采用协程式合作调度，任务静态分配且无抢占；而RTOS将任务拆分为独立线程，支持抢占式调度和优先级管理，但切换时需保存完整处理器上下文。双方实现同一功能程序——LED每200ms闪烁一次（按钮按下时熄灭）、按键GPIO中断检测并更新原子标志、通过消息队列将按键状态字符串打印至串口。评判维度包括：中断处理延迟（用示波器测量GPIO中断引脚与线程响应引脚的时间差）、线程等待往返耗时、.text段程序大小、.data+.bss段静态内存用量及编程体验。作者预期RTOS在中断延迟和线程响应速度上占优，C程序因无运行时检查而体积更小，Rust因编译器仅跨await点保存变量而静态内存更省，异步模型在编程易用性上更胜一筹。
