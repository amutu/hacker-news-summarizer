## 1. 电梯

**原文标题**: Elevators

**原文链接**: [https://john.fun/elevators](https://john.fun/elevators)

电梯使用调度算法来决定哪部电梯响应哪个呼叫。最简单的算法是 **SCAN（扫描算法）**，电梯从底层到顶层往返运行。**LOOK（前瞻算法）** 在此基础上改进，只在到达最高请求楼层后便反向运行，这符合人们的普遍预期。

对于多部电梯的情况，中央调度器负责分配请求，通常分配给最近的电梯。性能通过**等待时间分布**来衡量，尤其是**p50**（中位数）和**p90**（最差情况等待时间），因为人们对长时间等待的记忆远比平均等待时间深刻。交通模式也很重要：早高峰从大堂前往高层区域的客流会产生最严重的等待，而午餐时段和楼层间交通则有所不同。

一种更智能的算法——奥的斯的 **RSR（实时调度算法）**，会根据接客预计到达时间、轿厢内载客量以及惩罚/奖励机制为每部电梯评分，以减少电梯扎堆并奖励附近空闲的电梯。它**每5秒重新优化一次**，允许在情况变化时重新分配任务。然而，在高客流量的情况下——当电梯满载且每层都停时，额外的规则无济于事——**LOOK 的性能可能优于 RSR**；在电梯数量较少的小型建筑中也是如此。

**目的楼层调度**（乘客在终端机上选择目的楼层，然后被分配到特定电梯）听起来很有前景，因为系统能提前知道目的地。然而，它通常比传统的上/下按钮产生**更差的等待时间**。关键原因在于其刚性：已分配的电梯无法更改，而 RSR 的重新分配灵活性比额外信息更有价值。

文章包含一个交互式模拟，展示了这些权衡。总的来说，电梯算法是复杂的，长时间等待并不意味着电梯忽视了你——它一直在平衡许多相互竞争的因素。
