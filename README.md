**原文链接**: [https://anderegg.ca/2026/10/08/i-guess-im-using-webp-now](https://anderegg.ca/2026/10/08/i-guess-im-using-webp-now)

作者使用 JPEG、PNG 和 SVG 等图像格式超过二十年，如今终于加入了 WebP 阵营。WebP 由 Google 于 2010 年发布，但各主流浏览器支持严重滞后：Chrome 2011 年接入，Edge 2018 年、Firefox 2019 年、Safari 2020 年才跟进。在此之前，WebP 仅被部分 CDN 选择性使用。加之 Photoshop 直到 2022 年才获得原生支持，且其"另存为 Web 格式"功能仍不支持 WebP，作者一直对此颇有微词。Google Lighthouse 工具也常在文件节省有限、格式支持尚不成熟时便催促改用 WebP，更添困扰。然而，作者近期从 Photoshop 转投 Pixelmator Pro 后，工具链体验大为改善。他在最新文章中发现，WebP 在相同视觉质量下文件体积明显小于 JPEG 和 PNG，且尚未遇到例外情况。作者并不意外 WebP 的优势所在，真正改变的是操作门槛的消失。如今他开始期待 JPEG XL 和 AVIF 等新格式——AVIF 已具备浏览器基础支持，Google 近日也宣布上线 JPEG XL 支持，作者寄望不必再像当初等 WebP 那样漫长等待。

## 8. APSW：另一个 Python SQLite 封装

**原文标题**: apsw: Another Python SQLite Wrapper

**原文链接**: [https://github.com/rogerbinns/apsw](https://github.com/rogerbinns/apsw)

APSW（Another Python SQLite Wrapper）是一个 Python SQLite 封装库，支持 CPython 3.10 及以上版本。该项目将 SQLite 完整的 C API 与 Python 的 C API 紧密对接，保持与 SQLite 和 Python 的同步更新，旨在让用户充分发挥嵌入式数据库 SQLite 的全部能力。功能上，APSW 涵盖全文搜索、会话管理、虚拟表、VFS（虚拟文件系统）、JSON 及 CArray 等模块，所有功能均可在同步代码中使用，并完全兼容各类异步框架。官方建议：若需将 SQLite 与其他数据库驱动互换使用，可选用 Python 内置 sqlite3 模块；追求 SQLite 完整特性及更佳开发体验时，则应选用 APSW。文档方面，项目提供使用教程与示例代码，并设有完整文档站点。社区交流首选 Python SQLite 讨论组，亦可通过 GitHub 讨论或邮件联系作者。版本通过 PyPI 以 pip 发布，更新公告发送至讨论组并提供 RSS 订阅。Bug 追踪通过 GitHub Issues 完成。项目采用 OSI 认证的开源许可。
